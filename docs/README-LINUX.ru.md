## 1. Состояние предварительной версии

Версия для Linux повторяет поведение версии для Windows 0.1.7 (замороженной и служащей образцом). Она публикуется как **предварительный выпуск GitHub (pre-release)** под метками `Linux-vX.Y.Z`: её никогда не выдают за «последний выпуск» репозитория.

**Что опробовано** (виртуальная машина Debian 12, рабочий стол GNOME, Python 3.11, настоящий аккаунт YouTube с выполненным входом в каждом браузере, октябрь 2026 года):

- **Cookie Firefox, Waterfox, Floorp и Zen Browser**: читаются при открытом и при закрытом браузере.
- **Cookie Google Chrome, Chromium, Brave, Vivaldi, Opera и Microsoft Edge**: читаются при **закрытом** браузере, после того как каждый браузер был один раз запущен и в нём выполнен вход в YouTube (см. [раздел 5](#s5)). Одиночная загрузка и Инспектор плейлистов сработали.
- **LibreWolf**: читаются только пока он открыт и вход выполнен (по умолчанию он удаляет cookie при закрытии).
- **Приватное видео** с cookie Firefox и плейлист из трёх видео, одно из которых приватное.
- **Пакеты**: AppImage и архив `.tar.gz` собирает CI на Ubuntu 22.04; пакет `.deb` собран, установлен, запущен и удалён в Debian 12; AppImage, архив и `.deb` запускались в виртуальной машине, а «Установить в меню» / «Удалить» опробованы мышью с AppImage (значок добавлен, затем убран из меню и с рабочего стола).
- **Язык и шрифт**: корейский выбран на машине без корейского шрифта; окно «Font needed» предлагает шрифт, он скачивается и проверяется, программа перезапускается, и текст читается.

**Что ещё не опробовано**:

- другие дистрибутивы (Ubuntu, Fedora, Arch, openSUSE…) и рабочие столы, кроме GNOME, включая KDE Plasma (KWallet);
- браузеры, установленные как Flatpak или Snap (кроме раскладки LibreWolf во Flatpak, которая была изучена);
- Vivaldi, Opera или Edge **без** установленных Chrome и Chromium (см. [раздел 5](#s5));
- архитектура aarch64 (программа её предусматривает, но пакеты собираются только для x86_64);
- настоящий компьютер с Linux, вне виртуальной машины (настоящие рабочий стол и оборудование);
- переводы: они ещё нуждаются в проверке носителями языка.

## 2. Установка

### Какой формат выбрать

| Формат | Для кого | Права администратора | Пункт в меню |
|---|---|---|---|
| **AppImage** | любой современный 64-разрядный дистрибутив | нет | «Установить в меню» (раздел 2.3) |
| **Архив `.tar.gz`** | то же, без AppImage и FUSE | нет | «Установить в меню» |
| **Пакет `.deb`** | Debian, Ubuntu и производные | да (`sudo`) | автоматически |
| **Исходный код** | разработчики, пробы | нет | нет |

Требования: 64-разрядный Linux (x86_64) из дистрибутива 2022 года или новее (glibc 2.35 или выше), так как пакеты собираются на Ubuntu 22.04.

**Если вы новичок в Linux**: «по-настоящему» устанавливается только пакет `.deb`, и только он появляется в менеджере программ. AppImage и архив — обычные файлы или папки, которые лежат там, где вы захотите: чтобы убрать их, их просто удаляют, как любой другой файл (разделы 2.2 и 2.5). Их настройки хранятся отдельно, в `~/.local/share/yt-dlp-GUI` (раздел 6), и переживают такое удаление.

Файлы находятся на [странице выпусков](https://github.com/harlockSuites/YT-dlp-GUI/releases): ищите метки `Linux-v…` с пометкой «Pre-release».

### 2.1 Проверка загрузки

Скачайте также `SHA256SUMS-linux.txt` в ту же папку, затем:

```bash
sha256sum -c SHA256SUMS-linux.txt --ignore-missing
```

Каждый имеющийся файл должен показать `OK`. Это доказывает, что ваш файл идентичен опубликованному, но не что он безвреден: исходный код и автоматическая сборка открыты.

### 2.2 AppImage

```bash
chmod +x yt-dlp-gui-X.Y.Z-x86_64.AppImage
```

```bash
./yt-dlp-gui-X.Y.Z-x86_64.AppImage
```

AppImage требует библиотеку FUSE 2:

| Дистрибутив | Пакет |
|---|---|
| Debian, Ubuntu 22.04 и производные | `libfuse2` |
| Ubuntu 24.04 и новее | `libfuse2t64` |
| Fedora | `fuse-libs` |

Без FUSE всё равно запустите его: он сам распакуется во временную папку:

```bash
./yt-dlp-gui-X.Y.Z-x86_64.AppImage --appimage-extract-and-run
```

AppImage не «устанавливается»: он не появляется в менеджере программ. Чтобы убрать его, удалите файл:

```bash
rm yt-dlp-gui-X.Y.Z-x86_64.AppImage
```

Чтобы найти AppImage в меню приложений со значком, используйте функцию **«Установить в меню…» внутри программы** (раздел 2.3): вводить команду не нужно.

### 2.3 Установить в меню (без администратора)

AppImage, запущенный двойным щелчком, не оставляет значка в меню приложений. В программе: меню параметров › **«Установить в меню…»**. Это окно:

- копирует программу в `~/.local/share/yt-dlp-GUI/app/`;
- записывает ярлык запуска `~/.local/share/applications/yt-dlp-gui.desktop` и значок `~/.local/share/icons/hicolor/256x256/apps/yt-dlp-gui.png`;
- добавляет, если флажок установлен, ярлык на рабочем столе (помеченный как «доверенный» для GNOME, когда есть утилита `gio`);
- затем предлагает «Обновить» (заново копирует запущенную версию) и «Удалить».

«Удалить» убирает только то, что создала установка, и **сохраняет ваши настройки** и скачанные инструменты. Ярлык без нашей внутренней метки (`X-YtDlpGui-Installer=1`) никогда не удаляется.

Ограничения: окно доступно из AppImage и из архива. Из исходного кода оно отсылает к AppImage; из пакета `.deb` объясняет, что программа уже есть в меню.

Если ярлык на рабочем столе показывает предупреждение: щёлкните значок правой кнопкой › «Разрешить запуск». Некоторые рабочие столы (GNOME по умолчанию) не показывают значки на рабочем столе: ярлык в меню работает в любом случае.

Чтобы убрать всё вручную:

```bash
rm -rf ~/.local/share/yt-dlp-GUI/app ~/.local/share/applications/yt-dlp-gui.desktop ~/.local/share/icons/hicolor/256x256/apps/yt-dlp-gui.png ~/Desktop/yt-dlp-gui.desktop
```

Если пакет `.deb` уже установлен, не используйте эту функцию: программа уже есть в меню, и появилась бы вторая запись «yt-dlp GUI» (сначала удалите `.deb` командой `sudo apt remove yt-dlp-gui`, если предпочитаете этот способ).

### 2.4 Пакет `.deb`

```bash
sudo apt install ./yt-dlp-gui_X.Y.Z_amd64.deb
```

Программа попадает в `/opt/yt-dlp-gui`, вместе со ссылкой `/usr/bin/yt-dlp-gui`, ярлыком в меню, значком и лицензией (`/usr/share/doc/yt-dlp-gui/`). Она зависит от `libc6 (>= 2.35)` и `libx11-6`.

Чтобы удалить её (ваши настройки в `~/.local/share/yt-dlp-GUI` никогда не затрагиваются):

```bash
sudo apt remove yt-dlp-gui
```

### 2.5 Архив `.tar.gz`

```bash
tar xzf yt-dlp-gui-linux-X.Y.Z-x86_64.tar.gz
```

```bash
./yt-dlp-gui/yt-dlp-gui
```

Чтобы настройки и инструменты оставались **внутри распакованной папки** (USB-накопитель, проба без следов), создайте пустой файл `portable.flag` рядом с исполняемым файлом:

```bash
touch yt-dlp-gui/portable.flag
```

Без этого файла данные хранятся в `~/.local/share/yt-dlp-GUI` (раздел 6).

Архив не «устанавливается»: он не появляется в менеджере программ. Чтобы убрать его, удалите распакованную папку:

```bash
rm -rf yt-dlp-gui
```

### 2.6 Из исходного кода

```bash
python3 yt-dlp-gui.pyw
```

Из исходного кода настройки и скачанные инструменты хранятся в той же папке, что и у установленных версий (`~/.local/share/yt-dlp-GUI`): повторная загрузка кода или удаление его папки их не стирает. Чтобы данные оставались в папке с кодом (проба без следов), создайте пустой файл `portable.flag` рядом с `yt-dlp-gui.pyw`.

Нужен Python 3 с Tkinter:

| Дистрибутив | Пакет |
|---|---|
| Debian, Ubuntu и производные, openSUSE | `python3-tk` |
| Fedora | `python3-tkinter` |
| Arch | `tk` |

### 2.7 Обновления

Ежедневная проверка (её можно отключить в меню параметров) ищет версии `Linux-vX.Y.Z`, включая предварительные, и **никогда** не предлагает версию для Windows. Она открывает страницу загрузки файла, соответствующего вашей установке (AppImage, архив или `.deb`); **ничего не устанавливается автоматически**. Чтобы обновить:

- **AppImage или архив, установленные в меню**: скачайте новый AppImage, запустите его, затем «Установить в меню… › Обновить»;
- **`.deb`**: `sudo apt install ./new-file.deb`;
- **архив, не установленный в меню**: распакуйте новый архив на место старого.

### 2.8 Удалить всё, включая данные

После удаления программы (разделы с 2.3 по 2.5), чтобы стереть также настройки, очередь и скачанные инструменты (yt-dlp, ffmpeg, deno):

```bash
rm -rf ~/.local/share/yt-dlp-GUI
```

Ваши скачанные видео никогда не лежат в этой папке.

## 3. Первый запуск и зависимости

При первом запуске мастер установки предлагает скачать **yt-dlp** (`yt-dlp_linux`), **ffmpeg** (архив `.tar.xz` официальных сборок yt-dlp) и **deno** из их репозиториев на GitHub. Суммы SHA-256 проверяются, права администратора не требуются, а файлы попадают в `~/.local/share/yt-dlp-GUI` (yt-dlp) и `~/.local/share/yt-dlp-GUI/bin` (ffmpeg, ffprobe, deno). Мастер остаётся доступным в меню параметров.

Обязательны только ffmpeg и ffprobe; deno рекомендуется (дополнительные звуковые дорожки). **AtomicParsley, MKVToolNix и aria2** необязательны: окно «Зависимости» показывает команду вашего менеджера пакетов, которую нужно скопировать в терминал. Программа никогда не запускает её сама. Те же команды:

| Менеджер пакетов | Команда |
|---|---|
| apt | `sudo apt install aria2 atomicparsley mkvtoolnix` |
| dnf | `sudo dnf install AtomicParsley aria2 mkvtoolnix` |
| pacman | `sudo pacman -S aria2 atomicparsley mkvtoolnix-cli` |
| zypper | `sudo zypper install AtomicParsley aria2 mkvtoolnix` |

## 4. Cookie браузера

yt-dlp читает cookie **локально**, в выбранном вами браузере (дополнительные звуковые дорожки, субтитры, приватные видео, контент для участников). По умолчанию программа предлагает пять самых используемых в Linux браузеров (Firefox, Google Chrome, Chromium, Brave, Vivaldi). Пункт **«Браузеры для cookies…»** меню параметров открывает окно «Браузеры для cookies», где предлагается 11: отметьте нужные; значок ✔ отмечает те, чья папка профиля существует на вашем компьютере.

| Браузер | Как его читает yt-dlp | Связка ключей | Папки профиля, в которых идёт поиск |
|---|---|---|---|
| Firefox | `firefox` | нет | `~/.config/mozilla/firefox`, `~/.mozilla/firefox`, Flatpak, Snap |
| Google Chrome | `chrome` | да | `~/.config/google-chrome` |
| Chromium | `chromium` | да | `~/.config/chromium` |
| Brave | `brave` | да | `~/.config/BraveSoftware/Brave-Browser` |
| Vivaldi | `vivaldi` | да | `~/.config/vivaldi` |
| Opera | `opera` | да | `~/.config/opera` |
| Microsoft Edge | `edge` | да | `~/.config/microsoft-edge` |
| LibreWolf, Waterfox, Floorp, Zen Browser | `firefox:` + папка профиля | нет | `~/.librewolf`, `~/.config/librewolf`… (та же схема для остальных), включая Flatpak |

У производных Firefox нет имени, известного yt-dlp: программа ищет их базу `cookies.sqlite` (до трёх уровней ниже их папок) и передаёт yt-dlp папку последнего использованного профиля. `XDG_CONFIG_HOME` учитывается, когда это абсолютный путь.

**Индикатор** рядом со списком показывает состояние: красный (отключено или сбой), оранжевый (не проверено или идёт проверка), зелёный (cookie прочитаны). Кнопка ↻ запускает проверку; подсказка объясняет ошибку. Проверка, прочитавшая **0 cookie**, никогда не бывает зелёной.

### Частые случаи

| Что вы видите | Вероятная причина | Что делать |
|---|---|---|
| «Extracted 0 cookies», затем «Sign in to confirm you're not a bot» | браузер не хранит cookie на диске (LibreWolf по умолчанию удаляет их при закрытии; профиль без входа; приватный режим) | оставить его открытым и с выполненным входом в YouTube либо отключить удаление cookie при закрытии в его настройках приватности |
| «Item does not exist!» с Chrome, Chromium, Brave, Vivaldi, Opera или Edge | yt-dlp не нашёл ключ браузера в связке ключей рабочего стола | один раз запустить браузер, войти в YouTube, закрыть его и повторить проверку; иначе [раздел 5](#s5) |
| «Could not copy Chrome cookie database» или «database is locked» | браузер блокирует свою базу, пока работает | закрыть его, затем повторить проверку |
| «Failed to decrypt» | cookie зашифрованы ключом, который yt-dlp не получил | [раздел 5](#s5) |

### Проверка браузера из терминала

Это лучший способ увидеть точную ошибку (замените `IDENTIFIER` идентификатором любого видео YouTube):

```bash
~/.local/share/yt-dlp-GUI/yt-dlp --cookies-from-browser chromium -v --simulate --no-playlist "https://www.youtube.com/watch?v=IDENTIFIER"
```

Строки, которые нужно найти: `Extracted N cookies from chromium` (N должно быть больше 0), `Chosen keyring: GNOMEKEYRING` (выбранная связка ключей) и `cookie version breakdown: {'v10': 0, 'v11': 50, …}` (cookie `v11` требуют связку ключей, `v10` — нет).

Для производного Firefox укажите папку профиля. Чтобы найти её:

```bash
find ~ -name cookies.sqlite -path "*librewolf*" 2>/dev/null
```

В установке Flatpak ищите в `~/.var/app`:

```bash
find ~/.var/app -name cookies.sqlite 2>/dev/null
```

Затем, с папкой, содержащей `cookies.sqlite`:

```bash
~/.local/share/yt-dlp-GUI/yt-dlp --cookies-from-browser "firefox:/path/to/profile" -v --simulate --no-playlist "https://www.youtube.com/watch?v=IDENTIFIER"
```

## 5. Связки ключей: ручные операции

### Для чего это нужно

Браузеры семейства Chromium (Chrome, Chromium, Brave, Vivaldi, Opera, Edge) шифруют свои cookie. Ключ шифрования хранится в **связке ключей рабочего стола**: GNOME Keyring (или совместимый аналог, через «Secret Service») в GNOME, XFCE, Cinnamon, MATE…, KWallet в KDE. Чтобы расшифровать cookie, yt-dlp запрашивает этот ключ у связки ключей. Firefox и его производным она не нужна.

Два полезных факта:

- **Ключ появляется только после первого запуска браузера.** В нашей виртуальной машине ошибка «Item does not exist!» исчезла, когда каждый браузер был один раз запущен и в нём выполнен вход в YouTube. Точная причина первого сбоя достоверно не установлена: связка ключей существовала, была связкой по умолчанию и была разблокирована.
- **Какую связку ключей использует yt-dlp**, зависит от определённого рабочего стола (переменные `XDG_CURRENT_DESKTOP` и `DESKTOP_SESSION`), согласно коду yt-dlp (октябрь 2026 года):

| Определённый рабочий стол | Связка ключей, которую использует yt-dlp |
|---|---|
| GNOME, Cinnamon, MATE, XFCE, Pantheon, Unity, Deepin, UKUI | GNOME Keyring (`GNOMEKEYRING`) |
| KDE 4, 5, 6 | KWallet (`KWALLET`, `KWALLET5`, `KWALLET6`) |
| LXQt, KDE 3, нераспознанный рабочий стол (только оконные менеджеры: sway, i3…) | никакая: простой текст (`BASICTEXT`) |

В последнем случае yt-dlp читает только cookie `v10`: если ваш браузер хранит ключ в GNOME Keyring, его cookie `v11` не будут расшифрованы. Тогда нужно принудительно указать связку ключей из терминала (раздел 5.6); программа пока не предлагает такой настройки.

Элементы, которые ищутся в связке ключей, называются «*имя* Safe Storage». Согласно коду yt-dlp, это **«Chrome Safe Storage»** для Chrome и Vivaldi, **«Chromium Safe Storage»** для Chromium, Opera и Edge, **«Brave Safe Storage»** для Brave. В нашей виртуальной машине Chrome и Chromium тоже были установлены и запускались: мы не знаем, работали бы Vivaldi, Opera или Edge сами по себе.

### 5.1 Существует ли связка ключей?

```bash
ls -la ~/.local/share/keyrings/
```

Вы должны увидеть файл `login.keyring` (связка ключей «login»). Далее: какая связка ключей является **связкой по умолчанию**?

```bash
gdbus call --session --dest org.freedesktop.secrets --object-path /org/freedesktop/secrets --method org.freedesktop.Secret.Service.ReadAlias default
```

Ответ `(objectpath '/org/freedesktop/secrets/collection/login',)`: связка по умолчанию есть. Ответ `'/'`: **нет ни одной**, перейдите к разделу 5.4.

### 5.2 Заблокирована ли она?

```bash
gdbus call --session --dest org.freedesktop.secrets --object-path /org/freedesktop/secrets/collection/login --method org.freedesktop.DBus.Properties.Get org.freedesktop.Secret.Collection Locked
```

`(<false>,)`: разблокирована. `(<true>,)`: заблокирована; откройте её в Seahorse (раздел 5.4), который запросит её пароль.

### 5.3 Есть ли в ней ключ моего браузера?

Выведите список элементов:

```bash
gdbus call --session --dest org.freedesktop.secrets --object-path /org/freedesktop/secrets/collection/login --method org.freedesktop.DBus.Properties.Get org.freedesktop.Secret.Collection Items
```

Ответ содержит пути, оканчивающиеся числом (`…/login/1`, `…/login/2`…). Чтобы прочитать имя каждого (измените список чисел):

```bash
for i in 1 2 3 4 5 6; do gdbus call --session --dest org.freedesktop.secrets --object-path /org/freedesktop/secrets/collection/login/$i --method org.freedesktop.DBus.Properties.Get org.freedesktop.Secret.Item Label; done
```

Вы должны увидеть, например, `Chromium Safe Storage`, `Chrome Safe Storage` или `Brave Safe Storage`. Пустые имена безвредны. Если имени вашего браузера нет: один раз запустите его, войдите в YouTube, закройте его и снова выполните эту команду.

### 5.4 Создание или разблокировка связки ключей в Seahorse

Установите Seahorse («Пароли и ключи») и связанные инструменты. Точная команда есть и в окне «Браузеры для cookies» программы:

| Менеджер пакетов | Команда |
|---|---|
| apt | `sudo apt install gnome-keyring seahorse libsecret-tools` |
| dnf | `sudo dnf install gnome-keyring seahorse libsecret` |
| pacman | `sudo pacman -S gnome-keyring seahorse libsecret` |
| zypper | `sudo zypper install gnome-keyring seahorse libsecret-tools` |

Затем откройте его:

```bash
seahorse
```

- **Нет связки ключей по умолчанию**: создайте её (кнопка «+» или меню Файл › Создать › связка паролей), назовите «Login», затем щёлкните её правой кнопкой › «Сделать по умолчанию». Точные надписи зависят от версии Seahorse.
- **Заблокированная связка ключей**: двойной щелчок или правая кнопка › «Разблокировать», затем введите её пароль (вводите его сами, программа его никогда не запрашивает).
- **Автоматический вход**: связка ключей, защищённая паролем, не может открыться сама, если вы не вводите пароль при начале сеанса; она остаётся заблокированной, пока вы её не разблокируете (или пока вы не используете один и тот же пароль для сеанса и для связки ключей).

Затем **запустите браузер, войдите в YouTube, закройте его** и повторите проверку (раздел 4).

### 5.5 KDE Plasma (KWallet)

В KDE yt-dlp обращается к KWallet (`kwallet-query`). Менеджер называется `kwalletmanager` (или `kwalletmanager5`) в зависимости от дистрибутива. Эта конфигурация **не была опробована** в наших тестах.

### 5.6 Принудительный выбор связки ключей для yt-dlp (терминал)

Программа позволяет yt-dlp выбирать связку ключей в зависимости от рабочего стола. Чтобы задать её принудительно, добавьте `+СВЯЗКА` к имени браузера (значения: `gnomekeyring`, `kwallet`, `kwallet5`, `kwallet6`, `basictext`):

```bash
~/.local/share/yt-dlp-GUI/yt-dlp --cookies-from-browser chromium+gnomekeyring -v --simulate --no-playlist "https://www.youtube.com/watch?v=IDENTIFIER"
```

Чтобы узнать, какую связку ключей Chromium использует на самом деле (команда взята из кода yt-dlp, здесь не опробована):

```bash
chromium --enable-logging=stderr --v=1 2>&1 | grep key_storage_
```

### 5.7 Без связки ключей: `--password-store=basic` (для опытных, не опробовано)

Chromium принимает `--password-store=basic`: тогда он хранит свой ключ в открытом виде (фиксированный, общеизвестный ключ) и шифрует новые cookie как `v10`, которые yt-dlp читает без связки ключей (`chromium+basictext`). **Это менее безопасно**: любая программа, которая может читать ваши файлы, сможет расшифровать эти cookie. Используйте это, только если понимаете такой компромисс; уже сохранённые cookie, вероятно, не перекодируются: войдите снова.

### 5.8 Крайняя мера

Если связка ключей повреждена, **сначала сделайте её резервную копию**:

```bash
cp -a ~/.local/share/keyrings ~/keyrings-backup
```

Удаление `login.keyring` стирает **все** хранящиеся в нём пароли (Wi-Fi, онлайн-аккаунты…): не делайте этого, не понимая последствий.

## 6. Где находятся файлы

Папка данных — `$XDG_DATA_HOME/yt-dlp-GUI` (по умолчанию `~/.local/share/yt-dlp-GUI`), если только `portable.flag` не лежит рядом с исполняемым файлом архива (или скриптом `yt-dlp-gui.pyw`).

| Файл или папка | Содержимое |
|---|---|
| `gui-config.json` | настройки (язык, браузер, папки, выбор браузеров…) |
| `download-queue.json` | очередь загрузок |
| `custom-blocks.json` | пользовательские блоки параметров |
| `yt-dlp` | исполняемый файл, скачанный мастером |
| `bin/` | ffmpeg, ffprobe, deno |
| `cmd/` | временные файлы конфигурации yt-dlp |
| `app/` | копия программы, сделанная командой «Установить в меню» |
| `~/.local/share/fonts/yt-dlp-GUI/` (вне папки данных) | шрифт Noto, скачанный для корейского, японского или китайского; чтобы убрать его: `rm -rf ~/.local/share/fonts/yt-dlp-GUI` |

## 7. Устранение неполадок

| Проблема | Подсказка |
|---|---|
| AppImage не запускается | запустить из терминала, чтобы прочитать ошибку; установить FUSE 2 (раздел 2.2) или добавить `--appimage-extract-and-run` |
| Ничего не отображается или ошибка библиотеки | проверить версию glibc: `ldd --version` должна показывать 2.35 или выше |
| Нет значка на рабочем столе | GNOME по умолчанию их не показывает; используйте меню приложений |
| Ярлык на рабочем столе с предупреждением | правая кнопка › «Разрешить запуск» |
| Перетаскивание между хост-системой и виртуальной машиной не работает | это функция VirtualBox (Guest Additions), а не программы |
| Интерфейс имеет неправильный размер | программа следует системным шрифтам (Tk); попробуйте другой размер системного шрифта |
| Обновление yt-dlp не удаётся | используйте «Обновление и диагностика» в меню параметров; иначе скачайте `yt-dlp_linux` и выберите его в окне замены (выбранный файл становится исполняемым) |
| Квадраты вместо текста (корейский, китайский, японский…) | в системе нет шрифта с этими символами; в Debian и Ubuntu: `sudo apt install fonts-noto-cjk` (~90 МБ), затем закройте и снова откройте программу; в других дистрибутивах установите пакет «Noto Sans CJK» своего дистрибутива; программа может сама скачать шрифт (корейский, японский, китайский) при выборе языка, без прав администратора |

## 8. Сообщить об ошибке

Кнопка «Сообщить об ошибке» готовит технический отчёт, в котором ваши папки, имя пользователя и адреса электронной почты скрыты; ничего не отправляется автоматически. Для Linux добавьте к нему:

```bash
cat /etc/os-release
```

```bash
echo "$XDG_CURRENT_DESKTOP $XDG_SESSION_TYPE"
```

и укажите, **как** вы установили программу (AppImage, архив, `.deb`, исходный код) и — при проблеме с cookie — **результат проверки из терминала** (раздел 4), не вставляя свои cookie.

## 9. Для разработчиков

Тесты (на виртуальном экране, настоящий экран не нужен):

```bash
xvfb-run -a python3 -X utf8 -m unittest discover -s tests -t .
```

Сборка пакетов (инструменты сборки: `pip install -r packaging/requirements-build.txt`, а также `appimagetool`, путь к которому задаётся переменной `APPIMAGETOOL`):

```bash
python3 packaging/build_linux.py
```

```bash
python3 packaging/build_deb.py
```

Результаты находятся в `dist/`. Для наилучшей совместимости собирайте на самом старом поддерживаемом дистрибутиве (glibc сборочной машины — это минимум, требуемый от машин, на которых запускается программа). Полезные проверки пакета `.deb`:

```bash
lintian dist/yt-dlp-gui_*_amd64.deb
```

Единственная известная ошибка оформления — `dir-or-file-in-opt` (программа размещена в `/opt`).

**Публикация**: проверить `__version__` в `yt-dlp-gui.pyw`, поставить дату у раздела версии в `CHANGELOG-linux.md`, сделать коммит, затем создать и отправить метку `Linux-vX.Y.Z`. Рабочий процесс «Release Linux» запускает тесты, собирает AppImage, архив и `.deb`, вычисляет суммы и создаёт выпуск как **предварительный (pre-release)**, но не как «последний выпуск» (проверка обновлений версии для Windows 0.1.7 не должна находить там метку Linux).
